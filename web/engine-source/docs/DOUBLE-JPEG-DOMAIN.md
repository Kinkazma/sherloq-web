# Stored JPEG double-quantization traces

`jpeg.multiple` retains SHERLOQ’s experimental `aligned-lattice-v1` method. It reads original stored luminance DCT coefficients and the stored quantization table. It does not recompress a selected crop or estimate coefficients from decoded pixels. The histogram frequencies, Gaussian weights, lattice search, sample gates and verdict thresholds remain the native method. A compatible trace does not establish malicious editing or a number of compressions.

A source domain selects complete original encoded8×8 blocks whose64displayed pixel positions are all admitted by the union of acquisitions minus exclusions. EXIF orientations1–8 map displayed membership to the encoded grid. Overlapping acquisitions count each block once. The full domain preserves the native complete-block convention: incomplete right/bottom encoded blocks are omitted, while every complete native block remains. The parser may read original entropy data needed to decode the file; only admitted coefficients update histograms and lattice statistics. A subsampled first-component grid that cannot represent this domain is explicitly unsupported instead of silently changing coordinates.

The isolated decoder uses libjpeg-turbo3.0.3 and Emscripten4.0.15 with a bounded imported heap and virtual-array backing. Scientific counts are integers; the existing native binary64 Gaussian and reductions remain on CPU. The short scoring stage is retained there rather than adding GPU setup and readback to every new file. Result caching avoids repeating any analysis for the same signed source domain.

Encoded byte loans, backing stores, native pointers, heap backing and output backing have ordered retryable retirement. Source errors keep their original identity, including falsy values. Cancellation cooperates at input windows, coefficient rows and scoring work; a completed publication may legitimately win the cancellation race. Original bytes and an earlier raster remain usable after cancellation.

Rebuild the isolated resource with `EMSDK` pointing to the pinned4.0.15SDK and `JPEG_BUILD_ROOT` to the pinned libjpeg build inputs, then run `python3 scripts/build-double-jpeg-stream.py`. The resource includes the original libjpeg licenses. Focused Node contracts are in `tests/double-jpeg-domain.test.mjs` and `tests/double-jpeg-owner.test.mjs`; the latter needs `--experimental-test-module-mocks`.
