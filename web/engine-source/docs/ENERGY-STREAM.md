# Scientific energy plane preparation over segmented sources

`src/energy-stream.js` supplies an internal primitive for the remaining segmented
ELA energy pipeline. It does not enable `ela.energy` for segmented sources yet.
Native panel references, global quantiles/statistics, automatic profiles and
connected-region segmentation still require a separate bounded implementation.

`segmentedEnergyPlane(image,quality,{budget,signal,onProgress})` consumes the
existing global RGB JPEG stream. It returns one full-resolution float32 plane in
RAM segments or the source's owned temporary session. `store.readInto` and
`store.visit` read its row-major bytes; `dispose()` releases this plane. Its
lifetime is bounded by the source session. This is scientific storage, not an
RGB display surface or a PNG visualization. Encoded JPEG reuse, progress and
cancellation follow SEGMENTED-ELA.md. No public API or UI contract is changed.

`createEnergyRows(width,height,{budget,write,signal})` accepts consecutive full
RGB bands through `push(original,decoded,{y,rows})`. Its awaited `write` callback
receives borrowed float32 bytes and global row coordinates, at most32 rows per
write. `finish()` requires every row and flushes the bottom reflected boundary;
`dispose()` releases work memory on all other paths. Consumers must copy bytes
they retain beyond the callback. Reentrant, incomplete and reordered input fails
explicitly. The primitive itself never retains a complete source or energy plane.

RGB absolute residual luminance keeps native float32 vector/scalar-tail rounding.
The7×7 box filter preserves the original horizontal and vertical binary64 rolling
order, including REFLECT_101 for width/height1 and other tiny images. Bands do not
restart the vertical recurrence. Workspace is one float32 gray row, seven
float64 horizontal rows, one float64 column recurrence and up to32 float32 output
rows: `width*(68+4*min(32,height))` bytes. The output's `4*width*height` bytes and
JPEG/source-window workspaces have separate shared-budget admission. Temporary
output is deleted on failure; completed encoded JPEGs remain reusable.

The60 native primitive references match all energy bytes with changing delivery
bands1/7/32/3, including tiny edges, odd widths and1MP noise. Input ordering,
incomplete delivery, consumer failure, memory refusal and cancellation are tested.
An integrated global-JPEG test verifies encoded reuse, exact energy and output
cleanup after cancellation. Run `node --test tests/energy-stream.test.mjs`.

Two native full planes for4103×5401 BigTIFF at qualities75/99 are generated by
`scripts/generate-energy-stream-reference.py`. The Chrome test uses a48MiB shared
budget and OPFS for source/JPEG/energy; it checks complete output hashes, partial
file deletion, native-exact retry from cached JPEG and final storage cleanup.
See `energy-stream-chrome-proof.json`; reproduce with
`node scripts/test-m5-browser.mjs --energy-stream`.

This qualifies only the primitive and stated OPFS sizes. IndexedDB, extremely
wide inputs and the complete segmented scientific ELA analysis are not claimed.
