# XFeat and LighterGlue: complete attention for intra-image copy detection

The XFeat checkpoint, its learned weights, feature dimensions, six layers and
native feature extraction remain pinned to the existing model resources. The
matcher evaluates the complete cross-attention key domain in bounded query
blocks. It does not truncate learned attention to spatial neighbors. The
learned self-attention stages remain complete.

SHERLOQ detects copies within one image. Its declared caller policy excludes a
cross-attention pair only when both entries identify the same source
observation. Distinct observations at the same coordinates remain distinct.
The spatial candidate policy is applied at final assignment, with its existing
membership, radius and minimum-distance rules. This policy is an intra-image
adaptation; it is not the authors' unmasked two-image control. ALIKED and
SIFT+LightGlue retain their existing path and are not qualified by this change.

For source domains with exclusions or separate acquisitions, the native CNN
input lattice is anchored to the Original coordinate phase modulo32. Literal
admitted RGB values and the common uniquely owned normalization population are
preserved. Synthetic positions contain the population mean before
normalization, hence exactly zero after normalization. Excluded RGB is never
read, and synthetic positions never contribute to normalization statistics.
The complete-source native preparation is unchanged. Removing context does
not imply equality to a full-source CNN evaluation.

Learned stages and the shared Softmax use the original CPU runtime artifact.
The optional WebGPU partition evaluates matrix products and final assignment;
it does not substitute a different model or alter thresholds. Its separate
runtime environment and tensors remain owned until sessions, tensors and
physical GPU resources acknowledge retirement. The CPU FMA anchor uses
increasing-K float32 FMA. An optional relaxed-SIMD implementation is used only
after comparison with the strict fmaf implementation on that runtime.

Numerical comparisons must distinguish the independent native implementation,
the browser CPU implementation, and WebGPU against that same CPU partition.
Agreement between browser CPU and GPU does not establish exact agreement with
the native backend. A rejected numerical or resource contract must not be
hidden by output filtering or by changing scientific thresholds.

## Automatic execution choice

Automatic execution compares two CPU pages and two GPU pages of identical
shape. Each page contributes once to the final scientific result. The first
page of each provider accounts for its cold execution; the second measures
service rate. Full preparation cost is included when projecting the remaining
complete partition. GPU is chosen only with a predicted ten-percent benefit.
This margin selects an execution provider, not a scientific threshold. Short
or incomparable page sequences stay on CPU.

Observations are retained only after the request, physical retirement and host
cleanup have succeeded. The cache is limited to eight shapes in a reserved
32KiB metadata arena. A previously admitted dual compiled runtime may remain
resident when later useful work selects CPU; CPU operators still use the
original CPU artifact. The complete context remains funded at its conservative
1600MiB admission, separately from metadata. Idle memory reclamation or image
closure waits for context ACK before returning that credit. A newly admitted
CPU-only context uses its separate 576MiB admission. These are ownership bounds,
not process-memory measurements. Callback failures are preserved; only owned
resource failures may trigger the acknowledged CPU fallback.

## Rebuild operator-only resources

Install ONNX1.19.0 and Emscripten4.0.15 in a development environment. Run:

```
python scripts/build-xfeat-glue-global.py --emcc /path/to/emscripten/emcc
```

The declarative ONNX sources and C source contain no learned weights. The
builder verifies every generated byte against `vendor/xfeat-glue-global/PINNED.json`.
The official ONNX Runtime and separately pinned learned assets remain unchanged.
Emscripten musl/LLVM notices are included with the operator resources; the
original XFeat and LightGlue authors and model licenses retain their credits.
