# Luminance gradient fields

The gradient panel defaults to Krawetz and offers three views: components and magnitude in RGB (default), colored orientation (HSV), and structure-tensor coherence. Supplementary controls live in an Advanced settings disclosure, collapsed by default. Its summary stays in the primary row while its body expands inline. Processor selection, Cancel and Reset precede that body in the shared command flow, so advanced controls cannot push them onto a following row. Display, intensity, equalization, luminance, physical-border mode, sampling and smoothing settings remain shared when switching operators, in individual tools and batch recipes. Old per-method profiles are not recalled by a method switch. Only a support unavailable in the named method adapts: fixed three-tap operators use 3; Farid uses 5 or 7. Inactive settings are retained for later use. There is no arrow view. The methods are Sobel, Krawetz, an experimental area-weighted disk, central differences, Prewitt, Scharr, Farid–Simoncelli, Gaussian derivatives and the eight-direction Kirsch compass. These are operators and views, not independent authenticity detectors.

Requests containing only the historical Sobel/Krawetz parameters keep the original arithmetic and RGB rendering. Explicit requests may use `view: "native"`, `view: "angle"` or `view: "coherence"`. At native Sobel/Krawetz settings, `view: "native"` is canonicalized to the unchanged historical request, including gray conversion, coefficients, boundary behavior, rendering, intensity and equalization. Explicit changes to support, sampling, prefilter or luminance opt into the extended operator. The original 3×3 derivative definitions are also retained for HSV/coherence at native operator settings: Sobel uses OpenCV integer gray and REFLECT_101, including its observed ROI extension; Krawetz uses integer-floor gray and available neighbors.

| Parameter | Meaning |
| --- | --- |
| `kernelSize` | Odd support size, 3–63 where defined. Scharr, Kirsch, central differences and the reconstructed Krawetz operator keep their three-tap definitions. Published Farid filters are available at 5 and 7 taps. |
| `sampleStep` | Spatial distance between kernel taps, 1–16 pixels. This expands support without resizing the source. Krawetz defaults to unit sampling and permits explicit extensions. |
| `sigma` | Gaussian derivative scale, 0.1–32, within the explicitly selected support. |
| `diskFill` | Disk diameter divided by the support width, 0.1–1. The experimental kernel integrates pixel-square areas inside this disk and forms normalized positional moments. It is not identified as Krawetz's original PDF implementation. |
| `preSigma`, `preSize` | Optional Gaussian prefilter, disabled at sigma zero; odd support 3–127. |
| `tensorSigma`, `tensorSize` | Gaussian neighborhood used for coherence, with explicit scale and odd support 3–127. |
| `luma` | Gamma-coded BT.601 luma, or linear-sRGB BT.709 luminance. Krawetz retains integer-floor conversion when BT.601 is selected; an explicit BT.709 selection uses the shared linear conversion. |
| `border` | Half-sample reflection, nearest boundary replication, or omission of unavailable physical neighbors. Krawetz defaults to omission; an explicit shared choice opts into the extended operator. Native Sobel retains REFLECT_101 at its original defaults. |

The larger Sobel supports use normalized binomial smoothing and the corresponding centered derivative. Extended Prewitt uses uniform transverse averaging and a linear-regression derivative; its 3-tap case is the standard operator. The seven-tap Farid coefficients are the published rounded coefficients; they are not invented extensions to arbitrary sizes.

Coordinates follow the displayed native raster: x increases right, y down. The RGB components-and-magnitude view maps signed horizontal/vertical derivatives around neutral 127 in R/G and magnitude in B, with source-wide admitted-domain reductions; Krawetz retains its own original direction/magnitude encoding. In HSV, hue represents the full signed angle, saturation is magnitude divided by the largest admitted magnitude, and value is `(127+128*saturation)/255`. Zero strength is neutral RGB(127,127,127); weak gradients remain near neutral instead of receiving full chroma. This is a documented display transfer, not a newly named scientific detector. Inversion rotates the signed vector by 180 degrees. Coherence is `(lambda_max-lambda_min)/(lambda_max+lambda_min)`, displayed in grayscale; a zero-energy neighborhood has coherence zero. Coherence is axial and does not retain the sign of the brightness transition. Intensity is applied before an explicitly selected common equalization, using the existing pipeline.

## Source domains and large images

Every acquired pixel remains an admitted center. Excluded pixels are omitted before luminance preparation, normalized prefiltering, neighbor differences and tensor averaging. They are never replaced with black observations. Outside the admitted domain, the original image is kept solely as a display background. A rectangular acquisition defines a new native boundary; independent acquisitions and arbitrary holes use the same membership-aware path. Recompression retains the existing admitted-context owner.

Calculation uses bounded row windows and complete halos. Intermediate float64 vectors and RGB results use the shared memory budget and can be paged through the source's temporary-storage owner. A support that cannot fit one complete native row and its halo is rejected; resolution, kernel, sigma and selection are not reduced to make a final request fit. Derivative caches separate sources, domain fingerprints, recompression, operator settings and numerical backend. View, intensity, equalization and tensor-display changes do not invalidate the derivative field. Cache storage is private; result surfaces remain independent.

## CPU, GPU and adaptive previews

CPU derivatives and tensor statistics use float64. WebGPU evaluates the derivative kernels in float32 on bounded bands; tensor statistics and HSV conversion remain on CPU. GPU work, buffers, mapping, device ownership, scheduling and acknowledged retirement use the common engine services. Explicit GPU requests report unavailability rather than pretending to execute on GPU. Automatic selection uses completed useful CPU work; a recoverable GPU failure retries the complete request on CPU after retiring the failed attempt. No synthetic runtime calibration is added.

Difference terms are paired along their own derivative axis, preserving an exact zero in the perpendicular axis on one-dimensional inputs. Kirsch uses exact cardinal directions rather than trigonometric approximations to zero. Before the non-native GPU upload, one admitted luminance reference is subtracted in float64; this removes a constant that the difference kernels cancel anyway and preserves faint variations after strong smoothing. Historical integer Sobel/Krawetz requests retain their original paths.

Only errors identified by the GPU owner authorize automatic CPU recovery, and only after acknowledged retirement. Source, callback and storage errors retain their identity. An unavailable automatic GPU path is not retried for every nearby parameter change; explicit GPU selection retries it. A memory refusal may be retried automatically after useful headroom returns. Temporary-cache cancellation and failed replacement preserve the previous cache and independent published results; cleanup attempts every owner even when another retirement fails. Scoped progress uses the same task-envelope contract as full-frame progress. Resident halo planning clips to actual image boundaries, including short, wide images whose support exceeds their height.

The numerical backends have separate cache identities. Float32 derivative arithmetic is not claimed to be bit-identical to float64, particularly at a zero vector or a Kirsch direction tie. Qualification results must state measured errors and browser versions.

The existing parameter-preview controller, source owners, worker, memory admission and adaptive timing feedback are reused. Preview projection changes only the explicitly provisional sampled request. Spatial steps, Gaussian scales and variable supports are projected to that grid; the final request retains the exact native parameters. Cost calibration separates operators and views and groups comparable supports rather than resetting for every decimal slider movement. The existing preferred 100 ms target and 200 ms fallback are retained. Observed 50–200 ms interactions are a qualification target, not a cold-start or all-device guarantee.

All existing common equalizations remain downstream of the gradient view, including their CPU/GPU choices, caches and streamed implementations. No equalization kernel or quality setting is replaced. Batch recipes retain the same parameters, equalization state and backend, and pass the existing scientific acquisition/exclusion domain to the common operation.

## Credit scope

The named operators retain their original research attributions below. Central differences are the standard finite-difference construction. The experimental weighted disk and the browser display/region integration were implemented for SHERLOQ; no separate upstream paper or exact Krawetz figure-24 implementation is claimed. Lindeberg and OrientationJ are mathematical references for Gaussian derivatives and local tensor analysis, rather than claims that their software is embedded here.
